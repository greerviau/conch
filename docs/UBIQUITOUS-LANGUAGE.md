# Conch terminology

- Conch: the local cross-platform desktop dictation app that uses configured repositories and explicit mappings to prepare agent prompts.
- Profile: a named set of the choices a recording uses: the Recognition language, the Recognition model, Enhanced cleanup, the repositories that supply Repository context, and Auto-accept. Every install has at least one; a new install has one named Default. The shortcut and the other Settings are global.
- Active profile: the profile the next recording uses. The user chooses it on the Dictation page, from the Profile submenu of the Menu bar icon, or on the Recording indicator during a recording. With one profile none of these show a profile.
- Profile switch: choosing another profile during a recording. The recording uses the new profile: the audio heard so far is recognized and cleaned again with it. A switch is refused once the recording stops, and a profile whose Recognition model is not installed cannot be chosen during a recording.
- Repository context: the vocabulary of the active profile's repositories available to one recording. It excludes foreground-app state and other repositories.
- Context snapshot: the vocabulary, mapping versions, and profile choices captured when a recording starts, replaced by a Profile switch.
- Explicit mapping: a user-defined spoken phrase or transcription-error phrase paired with exact replacement text, scoped globally or to a repository.
- Vocabulary index: locally extracted filenames, relative paths, and declared symbols with their repository and file origins.
- Raw transcript: the speech recognizer's output before explicit mappings or repository corrections.
- Repository suggestion: a proposed transcript edit derived from indexed vocabulary that requires user acceptance unless Auto-accept is on. It matches the exact words of an identifier, a spelled-out acronym, or a close misspelling of a multi-word identifier.
- Auto-accept: the opt-in profile choice, off by default, that accepts every repository suggestion whose candidates share one spelling, with no mapping conflict and no overlapping suggestion, before delivery. Each acceptance is an accepted edit that Undo reverses, and none saves an explicit mapping. It is captured in the context snapshot.
- Recognition hint: the short list of mapping replacements and identifiers that Conch sends the local recognizer as its initial prompt so it spells them correctly. It is not sent to cleanup endpoints. A recognized sentence that lists two or more hint terms in hint order, with at most one other item, is dropped as the recognizer's echo of the hint.
- Always replace: accepting a repository suggestion and saving an explicit mapping from the heard phrase to the candidate, so later recordings apply it without review.
- Result: the editable transcript after mappings and configured cleanup, with optional accepted suggestions and manual edits. Initial delivery copies it automatically and, while Automatic paste is on, pastes it into an eligible focused input; subsequent review edits require explicit copying.
- Push-to-talk: recording activation mode that starts on hotkey press and finishes on release.
- Toggle recording: recording activation mode that starts on one hotkey press and finishes on the next.
- Eligible focused input: the currently focused text-editable element that the app can identify with sufficient certainty and that is not a secure/password field.
- Automatic paste: the Settings choice, on by default, to paste the delivered result into an eligible focused input. Off copies the result only and needs no paste permission.
- Clipboard fallback: delivery that retains the result on the clipboard when automatic paste cannot be performed.
- Keep history: the opt-in Settings choice, off by default, that saves each delivered result and its raw transcript to the local database. Turning it off stops saving and keeps existing entries.
- History: the saved entries that Keep history produces, newest first, on the History page. Each entry holds the result text, the raw transcript, and the delivery time, and Conch keeps the newest 500. Copying an entry never pastes it.
- Logs: the page that lists the log entries, newest first, with a level filter, a source filter, search, Copy shown entries, Show log file, and a confirmed Clear logs. It is the place to look for what Conch did and why.
- Log entry: one timestamped line of the log with a level (Info, Warning, or Error), a source, a message, and optional details. Entries never hold audio, transcripts, result text, or source text, and absolute paths are shortened (the home directory to `~`, others to `.../file name`). The log is `conch.log` in the data directory, rolls over at 2 MB to `conch.log.1`, and is written whether or not Keep history is on.
- Status line: the one-line note under the result that names how the result was cleaned and delivered, including the reason for a Clipboard fallback. It links to Logs for timing and details.
- Basic cleanup: local deterministic removal of configured hesitation tokens with limited whitespace/punctuation repair. It always runs, and blank tokens leave the transcript unchanged.
- Enhanced cleanup: optional model-assisted transcript cleanup using managed local S1-mini or a configured local/remote endpoint, with Basic fallback on failure. Each profile chooses it, disabled by default; the endpoint, its model, and the remote confirmation are shared by every profile.
- Microphone: the input device Conch records from. System default follows the system input, and a chosen device that is not connected falls back to it.
- Protected span: transcript text that mappings or exact repository matches identify for preservation through cleanup.
- Recording indicator: the small, nonactivating overlay above other applications. It shows level bars and the duration while recording, a drawing spiral while processing, and text only when the result was copied without a paste or something failed. With more than one profile, a person icon and the active profile's name follow the duration while recording; clicking them lists the profiles for a Profile switch. Otherwise clicks pass through it.
- Indexed term: one entry of the vocabulary index. A file term is a relative path or file name; every other term is a declared symbol. The Repositories page lists a repository's indexed terms in pages of 100.
- Shortcut capture: the Settings control that records a pressed key combination while Conch pauses its registered recording shortcut.
- Chunk: a span of a recording that ends at a pause and is recognized while recording continues. The recognizer ends every chunk with terminal punctuation, so a cut inside a sentence adds a false sentence end. The audio after the last chunk is the tail.
- Speculative recognition: recognizing the audio since the last chunk once speech is followed by 0.3 seconds of silence, before the recording stops. If no further speech follows when the recording stops, its text is the tail's text; otherwise it is discarded. It never commits a chunk. It is off in the application: a speculation still running at the stop delays the tail.
- Stop-to-text time: the time from the end of a recording (hotkey release or Finish) to the delivered result. The Logs page records it with the time of each stage.
- Recognition model: the speech model that turns audio into the raw transcript, chosen in each profile from the models that support its Recognition language. Each declares one Recognizer engine and the languages it supports: Whisper models (English-only `tiny.en`, `base.en`, `small.en`, and multilingual Tiny, Base, Small, and Large Turbo) and Parakeet TDT v2 (English). Larger models make fewer errors and take longer per chunk.
- Recognizer engine: the worker program that runs a recognition model. Whisper models run on `whisper-server`; Parakeet models run on `transcribe-server`, which Conch builds on transcribe.cpp. Both answer the same loopback requests.
- Recognition language: the profile choice of the language a recording is spoken in, an ISO code from the Whisper language table or Auto-detect. English is the default. It selects which recognition models Settings offers (only Large Turbo offers Cantonese) and is captured in the context snapshot.
- Auto-detect: the Recognition language choice that lets the recognizer detect the language. The first chunk of a recording that has speech is detected, and the rest of that recording reuses the language it found. Only models that support more than one language offer it. It turns off hesitation-token removal, spelled-letter matching, and managed Enhanced cleanup, because each needs a known language.
- Hesitation tokens: the standalone filler words Basic cleanup removes, kept as one list per Recognition language. English starts with `um` and `uh`; other languages start empty.
- Spelled-letter matching: the sound-alike rule in `spoken.rs` that matches letters spelled by name ("pod gee see") to an all-uppercase identifier word. It has a letter-name table for English only.
- Voice detection: the Silero model that each recognizer engine runs before recognition so only speech reaches the recognizer. A chunk with no speech yields no text. Every recognition model download includes it.
- Worker: a bundled inference process (recognizer or managed cleanup) that Conch starts when recording starts, reuses across recordings, and stops after an idle period or on exit.
- Menu bar icon: the system tray icon that shows recording and processing state and offers Show Conch, a Profile submenu when there is more than one profile, an update action, the installed version, and Quit Conch. It shows no profile name in the menu bar itself. Closing the main window hides it and leaves Conch running behind this icon.
- Stable local signing: signing a macOS build with the persistent self-signed "Conch Local Signing" identity so its Accessibility grant survives rebuilds. Release builds sign with the same identity so the grant also survives updates.
- Release: a version published on GitHub with installers for each platform and the update manifest `latest.json`. A tag `vX.Y.Z` builds it as a draft; publishing it makes it visible to installed copies.
- Update check: Conch's request for `latest.json`, made shortly after launch and then daily unless Settings turns it off, or on demand from Settings or the menu bar icon.
- Updater key: the minisign key pair that signs updater artifacts. Its public half is in `tauri.conf.json` and its private half is a repository secret. It is separate from macOS code signing.
